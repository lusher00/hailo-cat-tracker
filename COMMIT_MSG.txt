Add multi-camera support: one pipeline per CSI camera

Every piece of camera state was a module global -- CAM_*, capture_loop,
detect_q, PUBLISHER, STATS, TRACKER -- so a second camera would have meant a
second copy of the pipeline. Move all of it onto a CameraPipeline instance
instead. Two cameras are now two instances.

Each camera gets its own capture thread, render thread, depth-2 queue, tracker,
stats and frame publisher, so a restart, a slow encode or a stalled client on
one camera cannot drop frames on the other. The NPU stays the single shared
stage, serialised by the existing _infer_lock.

Cameras
  - CAMERAS=auto (default) enumerates the CSI ports at startup via
    rpicam-hello --list-cameras; CAMERAS=0,1 forces them.
  - Camera 0 keeps the unprefixed env names (CAM_WIDTH, ROTATE_DEGREES,
    INFER_EVERY_N), so existing .env files and systemd units are unaffected.
    Camera N reads CAMN_* and falls back to whatever camera 0 resolved to, so
    only the differences need setting.
  - Autofocus flags are dropped for sensors with no focus actuator (IMX477,
    IMX219, OV5647). Passing --autofocus-mode to one of those makes rpicam-vid
    exit, which would otherwise surface as a camera restarting forever rather
    than an obvious error.

Detection is per camera and switchable at runtime
  Camera 0 detects; additional cameras come up as plain video, because two
  cameras sharing one Hailo-8L halve the inference rate each one gets. Toggle
  from the Cameras panel in the web UI, POST {"cameras":{"1":{"detect":true}}}
  to /api/config, or pin CAM1_DETECT=1. Turning it off retires that camera's
  live tracks so the event log closes those rows instead of leaving them open.

Event log
  Trackers are per camera, so track IDs restart at 1 on each and can collide.
  Events are keyed on (camera, track_id) now: adds a camera column, with an
  ALTER migration for existing databases (old rows become camera 0, which is
  what they were). Snapshot filenames, the CSV export and the webhook payload
  all carry the camera index; the snapshot cooldown is per (camera, class).

HTTP
  New: /video/<n>, /snapshot/<n>, /stats/<n>, /tracks/<n>, /cameras. The bare
  paths still mean camera 0.
  /stats keeps its top-level keys as totals across all cameras and adds a
  "cameras" array with per-camera detail.
  /events, /events/summary and /events.csv accept ?camera=.
  /metrics labels every series by camera; sum by (class)
  (hailo_detections_total) recovers the old single-camera number.

Web UI
  The stage is a grid built from the server's camera list -- side by side on a
  wide screen, stacked below 900px -- with a caption per camera showing fps,
  NPU time and a detect badge, plus a per-camera snapshot button. New Cameras
  card holds the detect toggles. Confidence is a typed number input rather than
  a range slider.

Logging
  Two capture threads calling print() were splicing each other's lines, since
  print() writes the text and the newline as separate calls. Tagged output goes
  through a lock now, and carries the camera name.

Tests
  The harness fakes two cameras: the stand-in rpicam-vid answers --list-cameras
  with an imx708 on port 0 and an imx477 on port 1, and renders a different
  scene per camera. Covers enumeration, CAMN_* overrides reaching only their
  own camera, per-camera streams and stats, enabling and disabling detection at
  runtime, camera-tagged events and snapshots, camera-labelled metrics, and the
  dropped autofocus flags. 71 checks, up from 39.

Docs
  README, INSTALL and SETUP updated for two cameras; install.sh env template
  gains CAMERAS and a commented CAM1_* block.
